# TQ3_4S SM75 FreeToken Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Beads is the authoritative task state.

**Goal:** Add a tested decode-first TQ3_4S weight path for Ornith 1.5 35B in FreeToken on RTX 2070, then measure it independently from KV quantization.

**Architecture:** Preserve type-46 blocks end-to-end, add a CPU oracle and GGUF compatibility layer, port the signed-WHT plus DP4A CUDA decode primitives, connect dense and fused-MoE vector paths, and gate a real-model A/B against the saved Q4_K_M control. Keep `tq4-nc` KV unchanged until a separate KV experiment.

**Tech Stack:** Python 3.12, PyTorch 2.11, CUDA C++ targeting SM75, GGUF, pytest, Beads, systemd-run benchmark services.

**Spec:** `docs/superpowers/specs/2026-08-30-ornith-tq3-4s-sm75-design.md`

## Global Constraints

- FreeToken is the only inference runtime.
- Target hardware is RTX 2070 8 GiB Mobile, i7-8750H, 32 GiB DDR4, and 1 TiB NVMe.
- Use the exact `turbo-tan/llama.cpp-tq3` type-46 algorithm as the source of truth.
- Keep experts packed across NVMe, RAM, PCIe, and VRAM.
- Keep KV on the current `tq4-nc` control during the weight A/B.
- Write a failing behavior test before each production change and commit each green slice.
- Save every experiment in `TESTLOG.md`, `CHANGELOG.md`, README summary tables, and `benchmarks/results/`.
- Do not download the roughly 17 GiB checkpoint until header, CPU, and CUDA gates pass.
